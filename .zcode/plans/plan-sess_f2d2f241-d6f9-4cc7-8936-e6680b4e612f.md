# Plan: Documento SDD para LOXAR

## Objetivo
Crear un documento de **Spec-Driven Development (SDD)** que transforme el proyecto de "vibe coding" a desarrollo guiado por especificaciones, estableciendo el `docs/superpowers/specs/SDD.md` como capa de verdad entre los requerimientos y el código.

## Principios SDD a aplicar (adaptados de `rZjEoes9HE4` + pragmatismo para LOXAR)

Dado que el contenido del video no fue accesible directamente, aplicaré principios reconocidos de SDD alineados con la filosofía del proyecto:
1. **Specs como fuente de verdad**: toda feature/arquitectura tiene un spec antes de implementar
2. **ADR obligatorios**: decisiones arquitectónicas >500 LOC o que tocan límites de módulo → ADR
3. **Trazabilidad código↔spec**: todo archivo touched se referencia a su spec + ADR
4. **Acceptance criteria ejecutables**: cada spec tiene criterios de aceptación medibles (build, typecheck, tests)
5. **Separación producto/arquitectura/código**: el `what/why` vive en specs; el `how` vive en código

### Sección 2: Taxonomía de artefactos
- **Specs** (feature/arquitectura): `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`
- **ADRs** (decisiones arquitectónicas): `docs/superpowers/specs/ADR-NNN-<slug>.md`

- **Test plans** (estrategia): sección dentro del spec

### Sección 3: SDD Workflow (checklist obligatoria)
1. Spec → 2. ADR (si aplica) → 3. Plan → 4. Implementación → 5. Verificación → 6. Commit con referencia
